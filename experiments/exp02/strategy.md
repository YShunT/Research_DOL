# exp02：NAPL型の地点別LSL重みの低ランク化（実装済み・未実行）

## 実験目的

地点ごとに独立したLSLを持つ[exp01](../exp01/report.md)を基準に、**地点別LSLの292次元パラメータと、そのオンライン更新にどれほど冗長性があるか**を検証する。NAPL型「共通重み＋低ランクな地点別ずれ」を導入し、事前に決めた全rankで①共通重みあり・`E`のみ更新、②同じモデルを更新しないfrozen、③共通重みなし・`E,B`を更新、の3条件を比較する。4指標と更新コストを可視化する。

主命題は、**warm-upで学習した共通基底`B`をオンラインでは固定し、少数の地点係数`E`を更新するだけで、変化する時空間データへの予測適応を維持できるか**。同一checkpointのE-only対frozenを主比較とし、オンライン更新自体の利得を分離する。共通重みなし・`E,B`更新は別構造かつ可動基底の比較対象であり、単に3条件の精度が近いだけで「固定基底で十分」「共通重みは不要」「元LSLの関数も低ランクで表せる」とは結論しない。

共有するのは**LSLの重みベクトル**で、生成後の各地点LSLはexp01と同じ`32→4→32`、dropout 0.5、ReLU、残差加算を行う。[DOL論文](https://www.ijcai.org/proceedings/2025/0372.pdf)と同じく、入力埋め込み→LSL補正の加算→Graph WaveNet→予測器という前後の配置を保つ。

## NAPL型LSLと更新範囲

77地点のLSL重みを1地点あたり292個のベクトルに並べる。内訳は下射影`32×4+4=132`、上射影`4×32+32=160`。以下の式から各地点の重み`θ_n`を生成し、元のLSLと同じ順番でMLPとして適用する。

```text
Θ = 1 θ_shared^T + E B                  Θ ∈ R^(77×292)
θ_shared ∈ R^292, E ∈ R^(77×r), B ∈ R^(r×292)
θ_n = θ_shared + Σ[k=1..r] E[n,k] B[k,:]
h̃_n = h_n + LSL(h_n; θ_n)
```

`r`は**292次元の地点別重みのずれを表す基底ベクトルの本数**で、LSLの中間幅4ではない。地点間で共有する`θ_shared,B`と、地点ごとの係数`E`をwarm-upではすべて学習する。共通重みありの`r=0`では`E,B`がなく、77地点が同じLSLを使う対照になるが、**LSLなしではない**。共通重みなし条件では`θ_shared`を**パラメータ自体から除外して`Θ=EB`**とする。「ゼロに初期化して学習する」のではない。重みを生成してからReLUを通すため、非線形関数の出力を混ぜる前案とは一般に等価でない。

E-onlyなら`B,θ_shared`がonlineで固定されるため、`Θ(t)−Θ(0)=[E(t)−E(0)]B`。つまり地点別の**重み更新方向が共通の高々`r`次元の部分空間に制限される**。共通重みなしの`E,B`更新では`B`も動くので、「各時点の重みを低ランクに表せた」ことと「更新方向が固定基底で足りた」ことは同じ主張ではない。非線形LSLの**出力差**までrank `r`になるとは限らず、そこは実測する。

共通重みありのE-onlyとfrozenは、**同じrank・seedの最良warm-up checkpointから分岐**する。共通重みなしは別構造なので、同じrank・seedで別途warm-upする。online optimizerとSMBは各更新条件で新規初期化し、同じデータ順・乱数seed・教師遅延・SUMを適用する。予測器本体はどの条件でも固定する。

|条件|LSL重み|Awake時の更新|主に分かること|
|---|---|---|---|
|共通重みあり・E-only（主条件）|`Θ=1θ_shared^T+EB`|`E`のみ。`θ_shared,B`はwarm-up後に固定|固定基底上の地点別適応|
|共通重みあり・frozen（対照）|同じ`Θ=1θ_shared^T+EB`|なし|同一checkpointでのE-only更新の利得|
|共通重みなし・EB-update（比較）|`Θ=EB`|`E,B`の両方|共通オフセットなし・可動基底という別設計の到達性能|

共通重みありのLSL保持数は`292+77r+292r=292+369r`、E-onlyのonline更新数は`77r`、frozenのonline更新数は0。共通重みなしの保持・online更新数は`77r+292r=369r`。exp01の独立LSLは保持・online更新とも`77×292=22,484`。`r=0`の共通重みありE-onlyはfrozenと同一なので重複実行しない。共通重みなしの`r=0`は全LSL重みが0となり、LSLなし対照と同じなので、別途二重に学習しない。保持数、学習対象数、実測の時間・GPUメモリを別々に報告し、少パラメータだから高速だとは仮定しない。

## rankの事前設定と実験規模

**`r ∈ {0, 1, 2, 4, 8, 16, 32, 48, 64}`をonline結果を見る前に固定する。** 0は完全共有、1〜8は低ランク側、16〜32は中間、48は元LSLに近いパラメータ数、64は元LSLを超える高容量の参考点。小さい側は倍々に増やし、パラメータ効率の境界を読むため48を追加する。**この実験は単一の最適rankを選ばず**、rankによる精度・適応利得・パラメータ数・計算コストの変化を調べる。64まで改善し続けた場合は「この範囲で飽和未確認」と報告する。

|rank `r`|共通重みあり保持数|E-only更新数|共通重みなし保持・EB-update更新数|位置付け|
|---:|---:|---:|---:|---|
|0|292|0|0|共通LSL対LSLなし。オンライン更新なし|
|1|661|77|369|最小の地点差|
|2|1,030|154|738|低容量|
|4|1,768|308|1,476|低容量。元LSLの中間幅4とは別|
|8|3,244|616|2,952|提示図の`NAPL_r8`|
|16|6,196|1,232|5,904|中容量|
|32|12,100|2,464|11,808|高容量でも元LSLより少ない|
|48|18,004|3,696|17,712|元LSLの約80%の保持数|
|64|23,908|4,928|23,616|元LSLより多い参考点|
|exp01：地点別LSL|22,484|22,484|—|rank軸上の点ではなく基準線|

`r>0`の全rankで3条件を5 seedずつ実行する。`r=0`は共通重みありfrozenとLSLなしを対照として扱い、更新対象のないE-only/EB-updateは重複実行しない。exp01の5 seed結果は比較基準として再利用し、重みは流用しない。計算量が大きいため、まず各構造のseed 42で形状・勾配・更新対象・数値安定性を点検する。rankやseedの欠測は隠さず報告する。

## 全rank・3条件の実行計画

|条件|warm-up|online|比較の位置付け|
|---|---:|---:|---|
|共通重みあり：E-only / frozen|9 rank × 5 seed = **45回**|`r>0`のE-only **40回**＋全rankのfrozen **45回**|同一checkpointの対応比較で係数更新の効果を測る|
|共通重みなし：EB-update|8 rank × 5 seed = **40回**|**40回**|別途warm-upした可動基底モデルとの性能・コスト比較|
|LSLなし（共通重みなし`r=0`相当）|5 seed = **5回**|frozen評価 **5回**|LSL自体の寄与を確認|

合計は**90 warm-up＋130 online実行・評価**（補助診断は別）。すべてのrank・seedは結果を見る前に固定する。共通重みありは各warm-upの最良validation checkpointからE-onlyとfrozenに分岐する。共通重みなしは同じrank・seedでもcheckpointを共有できず、別途warm-upする。LSLなしは`h̃=h`として独立に学習し、共通重みなし`r=0`の結果にも対応させる。共通重みあり`r=0`とは区別する。

共通重みなしの`E,B`は両方を非ゼロの適切なスケールで初期化し、生成`θ_n`の初期ノルム・勾配を共通重みありと比較・記録する。比較条件は同じwarm-up/online期間・seed・評価式を使うが、異なる構造、初期化、warm-up済み重み、オンライン更新対象の差は残る。**E-only対frozenは更新の有無を分離できるが、E-only対EB-updateは`θ_shared`の有無と`B`の可動性を分離できない**。後者から「共通重みが不要」「可動基底が必要」と因果的に断定しない。

## 補助診断：元LSLの補正関数を直接近似する

全モデルを学習し直したrank比較だけでは、バックボーンがLSLの不足を補えるため、**exp01のLSL自体に冗長性があるとは断定できない**。そこでexp01の各seedの最良warm-up checkpointを教師にし、入力射影・Graph WaveNet・出力層を固定する。教師のtrain入力から得た地点別32次元特徴`h_n`に対する元LSL補正`f_n^{exp01}(h_n)`を対象に、rank別のNAPL学生LSLだけを学習し、同じ特徴に対する補正出力の差を最小化する。予測ラベルやonline入力は学生の学習に使わない。

rank一覧は主実験と同じとし、教師checkpointごとに独立に近似する。validation特徴で地点別・全体の補正関数RMSEと、教師の補正RMSに対する相対誤差を記録する。さらに**教師のバックボーンを固定したまま**学生LSLだけと入れ替え、validation予測の4指標と教師予測との差を測る。これを`figures/rank_vs_lsl_function_error.png`（rank別の補正関数誤差）と地点別の図にする。これは**warm-up時点の関数近似**であり、online更新の冗長性や新しいデータ種への一般化を直接証明しない。別の隠れユニット順でも同じ関数を表せるため、生の292次元重みのPCAだけで判断しない。

## 固定条件・結果の解釈

データと隣接行列のSHA-256、Chicago-Tの77地点、train/validation/online=20/5/75%、入力・予測長12、Graph WaveNet、warm-up・early stopping、SMB/EM、Awake/Hibernate、12ステップ教師遅延、最良validation checkpoint、seed 42〜46をexp01に合わせる。NAPL以外のモデル・評価方法は変更しない。onlineでは未来ラベルを使わず、Awake時だけ対象パラメータを更新する。共通重みありでは`θ_shared`が通常のLSL相当のスケールになるように初期化し、`r>0`では両構造とも`E,B`を**両方ゼロにはしない**。生成重み・出力・勾配の初期スケールを記録する。異なるrankで同じseedでも初期重みが厳密に同一とは限らず、対応seed比較の限界として扱う。

warm-up checkpointの選択にはexp01と同じvalidation基準を使うが、**rank自体はvalidation・onlineの結果で選抜しない**。両構造とも事前設定した全rankを実行し、良いrankを1つに絞らず、各rankで何が維持・改善・悪化するかを報告する。異なるrankの数値差は、表現容量やwarm-up結果の違いも含むため、オンライン適応の効果は同一rank・checkpointのE-only対frozenで読む。

## 指標と可視化

各条件・seedのonline全期間で、**MAE、WMAPE、sample-wise RMSE、global RMSE**をexp01と同じ式で求める。global RMSEは各seedの全予測要素でMSEを集約してから平方根、sample-wise RMSEは各予測窓の12ホライズン×77地点のRMSEを窓間平均。seedを連結してRMSEを計算し直さない。5 seedの平均±標本標準偏差（`ddof=1`）とexp01同一seedとの差を保存する。exp01の参考平均はMAE 0.703025、WMAPE 36.1154%、sample-wise RMSE 2.008994、global RMSE 2.243869。

Matplotlibで`figures/rank_vs_metrics.png`を作る。**2×2の4パネル**で横軸を離散的なrank `0,1,2,4,8,16,32,48,64`、縦軸をそれぞれMAE、WMAPE（%）、sample-wise RMSE、global RMSEとする。`r>0`では共通重みありE-only・frozen・共通重みなしEB-updateの3系列を、seed平均の線・±標準偏差のエラーバー・seed個別の淡い点で表示する。`r=0`では共通重みありfrozenを1点、共通重みなしEB-updateの位置に同等のLSLなし対照を1点置き、E-onlyの点は置かない。exp01平均を水平破線、相対1%悪化線を補助線で示す。横軸は候補の等間隔表示なので線の傾きをrankの数値差として解釈しない。軸の範囲と単位を明記し、元データのrank×seed表も保存する。

`figures/rank_vs_adaptation_gain.png`では、同一checkpointの`誤差(frozen)−誤差(E-only)`をrank別に示す。0より大きければ係数更新が有利。全期間と事前に定義した変化後期間を分け、各seedの対応差と平均±標本標準偏差を描く。共通重みなしEB-updateとの差は別checkpoint・別構造の**性能差**として示し、更新対象だけの効果とは呼ばない。

別図`figures/rank_vs_cost.png`では横軸rank、縦軸をLSL保持数・online更新数・実測推論時間・Awake更新時間・GPU peak memoryに分け、精度と効率を同時に読む。**同じrankでも3条件の保持数・更新数は異なる**ため、系列を分ける。さらに`figures/accuracy_vs_update_cost.png`で「相対MAE/相対global RMSE悪化率」と「元LSLに対する更新パラメータ削減率」の散布図を作り、Pareto関係を示す。**固定評価対象ではWMAPEはMAEの定数倍**なので4指標として併記するが、独立したrank判断ではMAEとglobal RMSEを特に重視する。Matplotlibは`pyproject.toml`と`uv.lock`に依存として追加済み。実装時に図の生成コマンドを残す。

## 「地点別更新が効いたか」の診断

1. **同じcheckpointからのonline分岐**：全`r>0`で共通重みありE-onlyとfrozenの同じ予測窓を比較する。区間別のMAE/global RMSEと`誤差(frozen)−誤差(E-only)`を時系列で描く。正なら係数更新が有利。区間の件数、5 seedの対応差、更新回数、更新時間も併記する。「有意差なし」を「同等」の証明とは扱わない。共通重みなしEB-updateとの誤差差も示すが、別checkpointとの比較として明示する。
2. **地点係数・生成されたLSLの変化**：warm-up終点と事前に固定した週境界で軽量snapshotを取り、`E_{n,:}`の変化を地点×時間ヒートマップにする。同時に`θ_n(t)`とLSL補正出力の変化量を測る。E-onlyでは`θ_shared,B`が不変であることを検証し、共通重みなしEB-updateでは`B`の変化も記録する。全地点に共通する移動と地点係数による移動を混同しない。
3. **関数上の効果**：train入力から事前に固定した参照サンプル集合`G`を作り、**各試行自身のwarm-up済み入力射影**で32次元特徴`h(x)`に変換してからLSLへ通す。`D_n(t)=sqrt(mean_{x∈G} ||LSL(h(x);θ_n(t))−LSL(h(x);θ_n(0))||²)`を可視化する。入力射影はonlineで固定する。地点別の補正の変化と後続期間の誤差差を突き合わせる。単なる係数ノルムの増加は予測改善の証拠としない。
4. **データ変化後の効果**：online期間の完了済み観測だけを使い、地点別に直近2期間の入力分布差を記録する。期間長、入力のtrain基準の標準化方法、分布距離（例：固定帯域のMMD）、安定/変化の区分境界をtrain/validationのみで先に固定する。各境界時点で**過去の2期間**から変化量を計算し、**その後の期間**のE-only対frozenの対応誤差差、累積誤差、回復過程を比較する。EB-updateとの性能差も別構造の参考比較として示す。季節性がある場合は比較窓を同位相に揃える。データ種を前提にした`y=0`や`y≤8`の閾値を主判定には使わず、誤差の大きい地点・期間が全体平均に隠れないよう地点別件数と誤差も報告する。

基底`B_k`の個々の意味は一意でない。可逆な基底変換でも`EB`が同じなら予測は変わらず、LSLのReLUによって重みの変化量と出力の変化量も一致しない。個々の「第1基底＝特定の需要現象」とは命名せず、**共有される更新部分空間、地点別の補正関数、予測改善**を解釈する。元LSLのonline更新の関数的rankをさらに直接測るにはexp01のonline snapshotが必要なので、計測付き再実行を別途明記する。

分布変化の実装は、train統計で標準化した系列に固定乱数の16次元RFF（RBF-MMDの近似）を適用し、直前2週の特徴平均の距離を地点別に測る。境界はtrain週ペアの距離の90パーセンタイルで先に固定する。

## 人流に限定しない設計上の境界

Chicago-Tは**最初の制御された検証対象**であり、この1データで「変化する時空間データ一般に有効」とは結論しない。モデル実装では地点数`N`、特徴チャネル数`C`、LSL中間幅`m`を設定から取り、1地点の重み長`P=2Cm+m+C`、`θ_shared∈R^P`、`E∈R^(N×r)`、`B∈R^(r×P)`として構築する。Chicago-Tの`N=77,C=32,m=4,P=292`は実験値であってモデルの固定値ではない。入力変数が複数あるデータに広げるときは入力射影の入力チャネルも可変にする必要がある。

変化量・誤差分析は特定地点、ゼロ需要、人数の絶対値を前提にせず、観測特徴をtrain基準で正規化して定義する。将来的な一般性は、交通速度など**異なる種類の時空間データ**で同じモデル変更と「変化後のE-only利得」を再評価して初めて検証する。exp02自身はChicago-Tでの方法検証に限定する。

## 判定基準・成果物

- **予測に十分な低ランク表現**：元LSLより少ない保持・更新パラメータ数のrankで、5 seed平均のMAE・global RMSEがexp01比で相対1%超悪化せず、sample-wise RMSEも大きく損なわない場合に言う。WMAPEも報告する。1%は研究上の暫定許容幅で、5 seedの「有意差なし」を統計的な同等性の証明とは呼ばない。
- **元LSL関数の冗長性**：固定バックボーンの補助診断で、小さいrankの学生LSLが元LSLの補正出力をvalidationで近似し、教師のvalidation予測も維持できた範囲に限って支持する。独立に再学習したrank別の予測精度だけからはこの主張をしない。LSLなし対照までexp01と同程度なら、LSLの有効性自体が弱い可能性を優先して報告する。
- **オンライン更新の冗長性・適応**：全`r>0`でE-onlyが同一checkpointのfrozenより改善し、変化量が大きい後続期間でも利得が残るかを見る。さらにexp01と近い予測精度を少ない保持・更新数で得られるかを判定する。`r=8`ならonline更新数はexp01の22,484に対して616。E-onlyとfrozenが同程度なら、低ランク適応の成功ではなく「この条件で更新の利得が小さい」と解釈する。
- **共通重みなしEB-updateの解釈**：`Θ=EB`がどのrankで予測精度を保てるか、基底`B`がどれだけ動くか、更新コストはどうかを記述する。共通重みありE-onlyとの差は`θ_shared`の有無だけでなく、`B`の可動性、保持数292個、初期化と別warm-upも含む。**この3条件だけでは「共通重みそのものが不要」「基底更新そのものが有利」とは判定できない**。必要なら後続実験で同一構造・同一checkpointの更新範囲だけを変える。
- `r=64`は元LSLよりパラメータが多いため、仮に最高精度でもパラメータ効率化の成功例には含めない。exp01のglobal RMSEは論文値と一致していないので、exp02の改善を論文再現と呼ばない。

## 実行方法

コード、依存、計画をcommitした後、リポジトリルートで実行する。`--run`は既定で事前設定した全rank・5 seedを順次実行し、完了済み条件は検証してスキップする。小規模な接続確認として、最初にseed 42・rank 8だけを実行することもできる。これは本計画からrankを除外・選抜する操作ではない。

```bash
uv run --offline --no-sync python src/run_exp02.py --run --seed 42 --rank 8
uv run --offline --no-sync python src/run_exp02.py --run
```

中断・失敗した条件は、`--retry-failed`を明示した場合だけ従前の成果物を`attempts/`へ退避して再試行する。完了済みcheckpointは保持する。

```bash
uv run --offline --no-sync python src/run_exp02.py --run --retry-failed
```

保存済み結果からPNGだけを再生成する場合、およびexp01のLSL補正関数の固定バックボーン蒸留を別途実行する場合は次を使う。蒸留は教師のtrain入力の固定間引き1024窓で学生LSLを学習し、validationの256窓で関数・予測誤差を測る。

```bash
uv run --offline --no-sync python src/run_exp02.py --plot
uv run --offline --no-sync python src/run_exp02.py --distill
```
